# 5 万条数据分布、T4 性能与训练参数选择

本文解释默认配置不是“拍脑袋”得出的，而是在 **学习价值、免费 T4 时长、显存和可观察结果**之间做的折中。统计对象是实际训练使用的前 50,000 条数据。你可以运行 `python remote/analyze_dataset.py` 复现统计。

> 注意：脚本当前取原数据文件的前 N 条，而不是随机抽样。因此下面是“本次教学子集”的分布，不能代表完整数据集；数据顺序也可能带来主题偏差。严谨实验应固定随机种子并做 shuffle/分层抽样。

## 1. 预训练数据是什么样

文件 `pretrain_t2t_mini.jsonl` 每行只有一个 `text` 字段。文本通常混合知识问答、指令回答、创作、日常对话等自然语言内容。预训练阶段不把它视为“问题—答案”，而是把整段文本切成 token，让模型预测下一个 token。

### 字符长度

| 指标 | 字符数 |
|---|---:|
| 样本数 | 50,000 |
| 平均 | 268.7 |
| P50 | 229 |
| P90 | 478 |
| P95 | 555 |
| 最大 | 3,366 |

### Token 长度

使用 MiniMind 自带 tokenizer：

| 指标 | token 数 |
|---|---:|
| 平均 | 203.5 |
| P50 | 176 |
| P90 | 366 |
| P95 | 422 |
| 最大 | 1,756 |
| 超过 256 token | 13,669（27.3%） |

这解释了为什么教学配置使用 `max_seq_len=256`：约 72.7% 的样本可以完整容纳，同时显存和训练时间明显低于 512。代价是约 27.3% 的长样本会截断。想保留更多长文本，可改为 384 或 512，但注意力计算成本会显著上升。

## 2. SFT 数据是什么样

文件 `sft_t2t_mini.jsonl` 每行包含一个 `conversations` 数组，消息由 `role=user/assistant` 和 `content` 组成；部分 assistant 消息还有 `reasoning_content`。

### 对话结构

| 指标 | 实测值 |
|---|---:|
| 对话数 | 50,000 |
| 平均消息数 | 7.1 |
| P50 消息数 | 6 |
| P90 | 12 |
| P95 | 14 |
| 最大 | 16 |
| user 消息总数 | 177,532 |
| assistant 消息总数 | 177,471 |
| 含 reasoning_content 的 assistant 消息 | 67,342（37.9%） |

### 单条消息长度

| 类型 | 平均字符 | P50 | P90 | P95 | 最大字符 |
|---|---:|---:|---:|---:|---:|
| user | 21.9 | 17 | 32 | 54 | 178 |
| assistant | 99.7 | 80 | 190 | 230 | 1,063 |

| 类型 | 平均 token | P50 | P90 | P95 | 最大 token |
|---|---:|---:|---:|---:|---:|
| user | 15.7 | 12 | 23 | 38 | 146 |
| assistant | 71.5 | 56 | 135 | 164 | 860 |

这些数字说明 SFT 不是 5 万个单轮问答，而是约 35.5 万条 user/assistant 消息组成的多轮对话。`max_seq_len=384` 比预训练的 256 更长，是为了保留更多上下文，但仍可能截断长对话。

## 3. 为什么选择 5 万条

5 万不是最佳数据量，而是教学档位：

| 档位 | 建议条数 | 目的 |
|---|---:|---|
| 冒烟测试 | 1,000–5,000 | 验证代码、显存和 checkpoint |
| 入门教学 | 50,000 | 一次免费 T4 会话内看完整链路 |
| 进一步实验 | 100,000–300,000 | 更稳定，但耗时和断线风险上升 |
| 追求效果 | 完整数据 + 多轮实验 | 已超出“快速免费教学”定位 |

从零训练时，5 万条远不足以获得可靠知识和推理能力。它只能让模型初步学会语言形式与指令格式。因此实测模型会产生病句、幻觉和答非所问，这是预期结果。

## 4. T4 实测训练时长

同一次运行中，数据子集生成完成时间约为 01:58:19：

| 阶段 | step | 产物时间 | 估算时长 |
|---|---:|---:|---:|
| 预训练 | 3,125 | 02:20:50 | 约 22 分 31 秒 |
| SFT | 6,250 | 02:56:08 | 约 35 分 18 秒 |
| 合计 | 9,375 | — | 约 57 分 49 秒 |

> 时长通过数据文件和最终权重的时间戳估算，会包含阶段切换与保存 checkpoint 的少量开销。免费 T4 的实际速度会因宿主机、I/O、Colab 调度和软件版本变化。

粗略吞吐：

- 预训练：约 2.3 step/s；batch 16，对应约 37 样本/s。
- SFT：约 3.0 step/s；batch 8，对应约 24 样本/s。
- 实测推理：约 35–79 token/s。

为什么 SFT step 更多？因为 50,000 / batch 8 = 6,250；预训练 50,000 / batch 16 = 3,125。梯度累积改变优化器更新频率和有效 batch，但不会减少 DataLoader 展示的 mini-batch step 数。

## 5. 参数为什么这样选

### hidden_size=512，num_hidden_layers=8

得到约 30.03M 参数。它足够展示 Transformer 学习过程，FP16 权重约 64 MiB，又能在 T4 16GB 上留出大量空间给激活值、梯度和优化器状态。更小模型跑得快但更容易只学到表面模式；更大模型从零训练需要更多数据，否则投入算力也不会自然变聪明。

### 预训练 batch_size=16，accumulation_steps=4

- 每个 mini-batch：16 个样本。
- 每 4 个 mini-batch 更新一次参数。
- 有效 batch：16 × 4 = 64。

这样既控制单步显存，又让梯度比 batch 16 更稳定。若 OOM，可改为 batch 8、accumulation 8，保持有效 batch 64。

### SFT batch_size=8，accumulation_steps=2

SFT 序列长度 384，单个样本通常比预训练更占显存，因此把物理 batch 降到 8。有效 batch 为 16。教学实验更重视尽快看到模型行为变化，而不是追求大型训练的最优全局 batch。

### epoch=1

一个 epoch 能走通完整流程，并把总训练时间控制在约 1 小时。小数据上反复训练容易过拟合和记忆模板。如果增加 epoch，应同时观察验证集 loss 和真实问题测试，而不是只看训练 loss。

### dtype

MiniMind 脚本默认使用混合精度。T4 对 FP16 Tensor Core 支持良好；是否适合 BF16 取决于运行时和脚本实现。遇到 dtype 兼容问题时优先使用 float16。

## 6. 如何设计自己的实验

每次只改变一个变量：

1. 固定 5 万条数据，比较 sequence length 256 与 384；
2. 固定参数，比较 1 epoch 与 2 epoch；
3. 固定训练时长，比较 15M、30M、60M 模型；
4. 记录训练时间、峰值显存、最终 loss 和固定测试问题；
5. 不要只凭一条回答判断模型质量。

建议至少保存以下实验表：模型参数量、样本数、token 数、序列长度、物理/effective batch、学习率、epoch、总时长、峰值显存、最终 loss、固定问题输出。
